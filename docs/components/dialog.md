# Dialog

- 언제 쓴다: 되돌리기 어려운 변경이나 영상 만들기 시작처럼 답이 있어야 다음으로 가는 일은 확인 창에서 한 번 묻는다. 실패 뒤 다시 시도할지 답을 받아야 할 때는 오류 창을 쓴다. 후보를 보거나 듣고 나서 「적용」으로 확정하는 일은 고르는 창을 쓴다. 진행 창은 영상 만드는 중 상단바 상태를 눌렀을 때만 열고, 평소에는 [상단바](topbar.md)에 진행만 남긴다.
- 언제 쓰지 않는다: 고르는 즉시 값이 바뀌면 `ValueField`의 값 메뉴를 쓰고, 답이 필요 없는 상태나 완료는 [인라인 안내](notice.md)나 [Toast](toast.md)를 쓴다. 저장 실패에 정해진 표면은 너비 440px인 판이며, 확인 창이나 자동으로 사라지는 Toast로 대신하지 않는다. 확인 창, 고르는 창, 진행 창을 서로 겹쳐 열지 않는다.
- variant: 확인 창은 화면 가운데에서 뒤를 막고, 아래 오른쪽에 회색 보조 단추를 먼저, 검정 주 단추를 끝에 둔다. 우상단 x는 없고 화면에 보이는 닫기 조작은 아래 단추뿐이다. 확인만 받으면 「닫기」 하나, 실패 뒤 재시도가 필요하면 빨간 제목과 회색 「닫기」, 검정 「다시 시도」를 쓴다. [공통 Dialog](../../frontend/src/components/Dialog/Dialog.tsx)는 `dialog`와 `alert` 역할, `neutral`·`warning`·`danger` 뜻을 제공한다. [ConfirmDialog](../../frontend/src/components/ConfirmDialog/ConfirmDialog.tsx)는 `alert`를 조립하며 Esc로 닫고 연 단추로 포커스를 돌린다.
  - 고르는 창은 대화 칸을 가리지 않고, 아래 단추 줄은 회색 「취소」와 검정 「적용」 순서다. 선택 전에는 적용을 끄고 우상단 x, Esc, 「취소」로 선택을 버린다. 보기만 하는 미리보기와 결과 카드도 우상단 x와 아래 조작을 두지만 선택·적용 변형은 아니다.
  - 진행 창은 작업 칸 가운데의 비모달 창이다. 우상단 x, Esc, 바깥 누르기로 닫고, 내부에 별도 「닫기」나 멈추기 단추는 두지 않는다. 멈추기는 상단바에서만 한다. 완료 뒤 결과 카드는 왼쪽 영상과 오른쪽 정보, 바닥의 「편집으로」·「mp4 저장」을 담는 별도 창이며, 닫으면 같은 편집 화면의 완성 상태로 돌아간다.
- 쓰는 토큰 / layer: 확인·오류 창은 `--size-dialog` 480px, `--space-24` 24px, `--radius-surface` 24px이며 높이는 내용에 맞춘다. 흰 `--popover`, `--shadow-float`, 진한 회색 24%의 `--overlay-dialog-scrim`을 쓴다. 오류 제목은 `--destructive` `#DC2626`, 본문은 `--sub` `#646B76`이다. [Dialog.css](../../frontend/src/components/Dialog/Dialog.css)에서 `--z-dialog` 90은 막, `--z-dialog + 1`인 91은 실제 창이다. 결과 카드도 이 층을 쓰며 결과 저장 알림만 [Toast의 92 예외](toast.md)를 쓴다. 현재 결과 창의 넓은 폭은 814px(382 + 360 + 24 × 3)이고, 좁은 데스크톱 배치 규칙은 미정이다.
  - 진행 창은 너비 480px, 여백 24px, 반경 24px과 검정 진행 표시를 쓴다. 현재 [진행 창 구현](../../frontend/src/features/edit/top-bar-status.tsx)은 `--z-panel` 45의 막, `--z-panel + 1`인 46의 창을 쓰며 뒤 화면의 조작을 막는 모달로 열지 않는다. 상단바의 진행 글자 자체에는 별도 layer가 없다.
  - 확인 필요: 겹침 규칙의 일반 층 표는 진행 창을 `--z-dialog` 90에 넣지만, 진행 창의 개별 규칙과 현재 앱은 비모달 45/46을 쓴다. 정본의 작업 칸 가운데와 달리 현재 진행 창은 상단바 아래의 화면 전체 폭을 기준으로 가운데에 놓인다. 막의 시작선도 데스크톱 상단바 56px이 아니라 작은 화면용 셸 값 64px을 읽는다.
  - 확인 필요: 배경 선택 정본과 공통 `Dialog`의 기본 폭은 480px이지만 모든 고르는 창의 고정 폭으로 정해졌다고 보지 않는다. 현재 소리 창은 [전용 CSS](../../frontend/src/features/edit/sound/choice-dialog.css)에서 여백 20px과 고스트 취소를 쓰며, 컨테이너 안에서 열면 공통 `Dialog`의 막을 그리지 않고 대상 너비를 따른다. 공통 창의 24px 여백·90/91과 고르는 창의 회색 취소 기준을 이 앱 동작과 구분한다.
- 쓰는 화면: [컨셉 확인](../../frontend/src/features/concept/concept-screen.tsx)은 공통 `ConfirmDialog`가 아닌 자체 모달이다. 편집은 [장면 확인](../../frontend/src/features/edit/scene-confirm.tsx), [변경과 순서 확인](../../frontend/src/features/edit/change-review.tsx), [목소리·BGM 선택](../../frontend/src/features/edit/sound/choice-dialog.tsx), [효과음 고르기](../../frontend/src/features/edit/scene-panel.tsx), [미리보기 크게 보기](../../frontend/src/features/edit/scene-preview.tsx), 상단바에서 여는 진행 창에 쓴다. 결과는 [결과 카드](../../frontend/src/features/export/result-card.tsx)에 쓰고 출력 실패는 [오류 화면](../../frontend/src/features/export/export-screen.tsx)에서 재시도를 제공한다. `ConfirmDialog`의 오류·삭제 예와 `RangeDialog`는 갤러리 사례이며, 앱의 변경·순서 확인은 별도 `Dialog` 조립이다.
  - 확인 필요: 기준선과 편집 정본 B는 배경을 미리 보고 적용하는 창으로 두지만 현재 [장면 편집](../../frontend/src/features/edit/scene-panel.tsx)은 배경을 즉시 바꾸는 `ValueField`로 열고, 효과음 창은 선택을 바로 추가하며 아래에는 고스트 닫기만 둔다. 옛 기준선의 옆에 붙는 전체 높이 효과음 창과도 다르다.
  - 확인 필요: 아래 회색 보조 단추 기준과 달리 현재 장면 시작·변경·순서 확인은 고스트를 쓴다. 공통 확인 창은 Esc로 닫히지만 [정지 장면 생성 창](../../frontend/src/features/edit/still-build.tsx)은 여닫힘 요청을 무시해 우상단 x·Esc·바깥 누르기로 닫히지 않는다. 이 생성 창을 영상 만드는 중 진행 창의 닫기 규칙으로 해석하지 않는다.
