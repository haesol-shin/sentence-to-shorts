# 인라인 안내와 배너

- 언제 쓴다: 상태가 특정 값이나 묶음에 붙어 있고 그 화면에서 계속 유효하면 인라인 `Notice`를 쓴다. 상태가 풀리면 사라진다. 그 값을 담은 면에 두고 다른 묶음 아래에 두지 않는다. 고르는 창 안에서도 그 창의 값에 대한 주의라면 쓴다. 화면 수준 상태는 특정 값의 안내와 나누어 본다. 현재 셸에서 대본 작업 상태를 알리는 `JobBanner`가 그 예다.
- 언제 쓰지 않는다: 이미 끝난 일을 잠깐 확인하는 데는 [Toast](toast.md)를 쓴다. 사용자가 답해야 다음으로 갈 수 있으면 [Dialog](dialog.md)를 쓰고, 실패를 고칠 조작을 함께 보여야 하면 실패 판이나 창을 쓴다. 인라인 안내 자체에는 닫기 x나 단추를 두지 않는다. 단추 이름이나 쓸 수 없는 이유를 잠깐 보일 때는 Tooltip을 쓴다.
- variant: [Notice](../../frontend/src/components/Notice/Notice.tsx)는 회색 알림(`neutral`, 기본), 주황 주의(`warning`), 빨강 오류(`error`) 세 뜻만 쓴다. 제목은 선택이고 오류 제목만 빨갛다. `banner`는 `Notice`의 variant가 아니다. [JobBanner](../../frontend/src/app/shell/job-banner.tsx)는 지금 셸에 있는 작업 상태 한 줄이며, 공통 `Banner` 부품이나 공통 배너의 닫기·쌓임·뜻 색 규칙은 없다.
- 쓰는 토큰 / layer: [Notice.css](../../frontend/src/components/Notice/Notice.css)는 부모 폭 100%, `--space-16`과 `--radius-content` 각 16px, `--icon-default` 20px, 보조 글자 15/22를 쓴다. 바탕 `--muted`는 `#F2F4F6`, 아이콘은 `--muted-foreground` `#646B76`, `--warning` `#B45309`, `--destructive` `#DC2626`이고 오류 본문은 `--sub`다. 안내와 배너는 흐름 안에 있으므로 별도 layer가 없다. 현재 `JobBanner`는 `--surface-muted`와 셸 글자 별칭을 쓰는 띠로, 안내 상자의 16px 반경과 아이콘을 물려받지 않는다.
  - 확인 필요: 공통 아이콘 기준선은 안내에 채운 아이콘을 쓰지만 현재 `Notice`는 선 아이콘을 그린다. 갤러리 설명은 뜻 색을 아이콘에만 쓴다고 하나, 겹침 규칙과 현재 CSS는 오류 제목에도 `--destructive`를 쓴다.
- 쓰는 화면: [첫 화면의 키 입력](../../frontend/src/app/api-key-block.tsx), [편집의 장면 확인](../../frontend/src/features/edit/scene-confirm.tsx), [변경 확인](../../frontend/src/features/edit/change-review.tsx), [소리 고르는 창](../../frontend/src/features/edit/sound/choice-dialog.tsx), [자막 문제](../../frontend/src/features/edit/captions/caption-issues.tsx), [출력 전 점검](../../frontend/src/features/export/precheck-panel.tsx)에서 대상 바로 곁의 상태를 보인다. [준비 안내](../../frontend/src/features/runtime/prepare-notice.tsx)는 `Notice`를 재사용하되 모델 준비가 실패했을 때만 바로 아래 오른쪽에 별도 「다시 시도」 단추를 둔다. [셸](../../frontend/src/app/workspace.tsx)은 연결 상태와 오류에 `Notice`를 쓰고, 작업 대기 중인 `JobBanner`는 작은 화면에서만 보이며 실패·중단은 데스크톱에서도 보인다. 성공하면 배너는 사라진다.
  - 확인 필요: 일반 안내에 닫기 조작을 두지 않는 규칙과 별개로, 지금 셸의 실행 오류와 [장면 편집 오류](../../frontend/src/features/edit/scene-panel.tsx)는 `Notice` 바깥에 닫기 조작을 둔다. 기준선은 저장 실패를 너비 440px인 판으로 정했지만, 그 판의 최종 형태와 자리·층은 겹침 규칙과 검토 기록이 갈린다. 현재 제품에서 이 전용 판은 확인되지 않으며 오류를 인라인 등 각 흐름에 남긴다.
- 갤러리 사례: [회색 알림](../../frontend/src/gallery/index.html?case=9-1-neutral), [주의](../../frontend/src/gallery/index.html?case=9-2-warning), [오류](../../frontend/src/gallery/index.html?case=9-3-error), [긴 안내](../../frontend/src/gallery/index.html?case=9-4-long), [창 안의 안내](../../frontend/src/gallery/index.html?case=21-2-long). `JobBanner`나 공통 배너 전용 사례는 없다. 마지막 링크는 창 안에서 `Notice`를 재사용하는 예이지 배너나 저장 실패 판 자체는 아니다.
