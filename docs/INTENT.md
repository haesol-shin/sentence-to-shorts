# INTENT

> 짧은 영상을 쉽게 만들고 싶은 사람이, 한 공간에서 원하는 포맷의 영상을 빠르고 적은 비용으로 만들고, 필요한 부분만 고친다.
>
> Anyone who wants to make short videos easily can create them in the format they want, quickly and at low cost, in one place, and change only the parts they need.

이 문서는 이 서비스가 누구를 위해, 왜 있는지를 적는다. 기능, 화면, 코드를 정할 때 이 문서와 맞지 않으면 이 문서를 따른다. 기능의 상세 동작은 [SPEC](SPEC.md)에 있다. 용어는 [GLOSSARY](GLOSSARY.md)를 따른다.

## 사용자 (user)

- 짧은 영상을 쉽게 만들고 싶은 사람이다.
- 주제는 학습에 한정하지 않는다.
- 한 주제로 여러 편의 영상(시리즈, series)을 만드는 사람도 포함한다.
- 서비스 지원 언어는 한국어와 영어다. 영상 언어(video language)는 사용자가 프로젝트마다 고른다.

## 목표 (goals)

- 원하는 포맷(format)의 영상을 빠르게 만든다. 포맷은 화면, 소리, 스토리를 포함해 영상이 주는 인상 전체다.
- 시간과 비용을 줄이면서 품질을 높인다.
- 사용자는 필요한 부분에만 손댄다. 나머지는 기본값과 추천으로 채운다.
- 한 공간에서 처음부터 끝까지 만든다.

## 원칙 (principles)

1. 비싼 일일수록 늦게, 작게 한다. 대본 확인, 장면 정지 화면 확인, 전체 생성 한 번, 바뀐 장면만 다시 생성하는 순서다.
2. 장면(scene) 단위로 만들고 고친다. 장면 하나를 고치면 그 장면만 다시 만든다.
3. 생성형 이미지·영상 모델을 쓰지 않는다. 화면은 코드로 렌더링한다. LLM은 장면 데이터와 대본만 정한다. 템플릿에 없는 포맷은 상위 모델이 템플릿 코드를 새로 쓰고 프리셋으로 저장한다. MVP에 포함한다.
4. 문장 입력과 카드 선택은 동등한 시작점이다. 모든 값은 기본값이 미리 골라져 있다. 원하는 사람만 세부 조정(fine-tune)을 연다.
5. 기본값과 추천은 정해진 순서로 채운다. 사용자 직접 입력, 참고 영상(reference video), 프로젝트 프리셋(preset), 주제 기반 LLM 추천 순서다.
6. 영상끼리 너무 비슷하지 않게 하면서 품질을 유지한다. 사용자는 항목마다 고정(lock)과 변화를 고른다. 고정한 항목은 프로젝트 안에서 같다. 변화 항목은 영상마다 바뀐다.
7. 소리가 비는 영상을 만들지 않는다. BGM은 기본으로 켠다. TTS는 자연스러움을 기준으로 고른다.
8. 작업마다 맞는 모델을 쓴다(model routing). 흥미와 스토리텔링이 중요한 대본은 상위 모델을 쓴다.

## 포맷을 받는 방법

- 포맷은 프리셋과 소스(source)로 받는다. 프리셋은 저장된 포맷이다. 소스는 참고 영상과 재료(material)다.
- 포맷 카드(format card)는 이야기 틀(story structure), 화면 틀(layout), 캐릭터 역할(character role), 말투(register)를 한꺼번에 채운다. 세부 조정에서 항목마다 바꿀 수 있다.
- 그림체(art style)는 포맷 카드와 따로 고른다. 화면 틀은 위치만 정하고 그림체가 모양을 정한다.
- 그림체 안에 테마(theme)가 있다. 테마는 배경, 대화창 모양, 색감이다.
- 캐릭터(character)는 그림체마다 부위 에셋을 조합해 만든다. LLM이 프리셋 캐릭터를 고쳐 쓸 수 있다.
- TTS 목소리는 프로젝트 안에서 같게 두는 것이 기본이다. 사용자가 바꿀 수 있다.
- BGM은 영상 분위기에 맞춰 영상마다 다르게 고른다.

## MVP 범위

- 흐름: 스토리(story), 시각(visual), 장면(scene), 소리(audio), 생성(generate) 다섯 단계다.
- 포맷 카드 3장: 「딱 3가지만 (Just 3 Things)」, 「○○로 치면 (It's Like…)」, 「만약 ~라면? (What If?)」. 세부 조정을 포함한다.
- 그림체는 계속 늘어나는 기본 묶음이다. 첫 기본은 픽셀(pixel)이고 2D 컷아웃은 첫 개발 빌드 뒤에 넣는다.
- 장면 다시 만들기(regenerate), 장면 순서 드래그, 프리셋 저장, 고정과 변화, 새 포맷의 템플릿 코드 쓰기를 포함한다.
- 재료는 붙여넣은 글로 받는다.
- 대화(chat)로도 영상을 고칠 수 있다. 카드와 선택지로 나타내기 어려운 취향을 받기 위해서다.
- 참고 영상을 자동으로 분석해 포맷을 채운다.
- 실행 형태는 사용자 수(한 명, 여럿)와 실행 위치(직접 실행, 서버 호스팅)를 나눠 설계한다. 런타임에 필요한 모델과 에셋은 코드가 준비하고, 사용자가 따로 설치하지 않는다.
- 화면은 모바일과 데스크톱에 맞춰 바뀐다(적응형 UI).
- 목표 길이는 30초, 1분, 2분 중에서 고른다. 기준일 뿐이고 영상을 자르지 않는다.
- 앱은 각자 컴퓨터(Windows, Linux)에서 설치 파일로 실행하고, 같은 코드를 서버 호스팅으로도 띄운다. 앱이 부르는 LLM은 API 키를 쓴다.

## 설계 기준 (design criteria)

- 결정: 레퍼런스에서 형식과 스타일을 가져와 새 스타일을 만들고, 사용자가 자기만의 것으로 고치는 것이 핵심 기능이다. 스타일은 매번 만들 수 있고 그 개수가 많아야 하며 커스터마이즈가 중요하다. 픽셀, 컷아웃 같은 고정 그림체는 점차 늘리는 기본 묶음이다.
- 기술 설계: 스타일 설정과 manifest는 데이터로 관리한다. 새 형태와 동작은 검증된 생성 코드로 확장한다. 생성 코드는 sandbox에서만 실행한다.
- 결정: UI 배치는 정해졌다. 시각 디자인의 글꼴과 대표색은 [ADR 0016](decisions/0016-use-selected-design-tokens.md)이 정한다. 나머지 값은 디자인 작업에서 정한다.
- 결정: 외부 의존성은 최소로 둔다. 코드는 복잡해지지 않게 쓴다. 판단 기준은 관리하기 쉽고 기능을 추가하기 쉬운지 하나다. 상속은 이 기준에 맞으면 쓴다. 코드 구조의 참고 저장소(레퍼런스)는 리뷰를 거쳐 정한다.
- 결정: 포트폴리오와 사업화를 고려해 설계한다. 특정 제출 요건에만 필요한 것은 바깥 층에 모아 나중에 빼거나 바꿀 수 있게 한다. 코드는 Apache-2.0으로 공개할 수 있게 둔다. 모델, 에셋, 음원은 상업 사용 가능 여부를 기록한다.

## 하지 않는 것 (non-goals, MVP)

- 생성형 이미지·영상·음악 모델(BGM 생성 모델 포함). 코드로 만든 음악은 여기에 들지 않는다.
- 타임라인 편집
- 사진으로 캐릭터 만들기
- 프로젝트 피드, 시리즈 화면, 공유, 로그인 (나중에 구현할 때 인스타그램 등 SNS를 참고한다)
